## New code and scope

**`scripts/phase1do-offline-registrar-witness-enrollment.mjs`** exports pure `assessRegistrarEnrollmentWitnessCandidate`, `witnessSigningBytes`, `WITNESS_ROLES`, and `DOMAIN`. It accepts original signed 1DM appointment packet, existing public registrar/registry comparison pins, **original in-memory 1DL operator session via 1DN**, strictly bounded exact-schema witness manifest, two separately supplied witness public-key pins, two domain-separated signed witnesses and explicit prior-checkpoint sequence/hash plus current canonical UTC verifier clock.

- The only permitted witness roles are `LEGAL_WITNESS` and `REGISTRY_WITNESS`. Each requires a distinct Ed25519 SPKI DER SHA-256, valid public-key PEM and unique key ID, cryptographically valid detached canonical Ed25519 signature in its **role-specific domain**. Neither witness key may equal registrar key. Comparison fingerprints are required as explicit separate input; no field that claims `independentlyVerified=true` is accepted.
- Witness manifest binds exact repository, source HEAD and pinned `main`, organization, registrar root SPKI SHA-256, corporate registry evidence digest, SHA-256 of exactly signed 1DM root appointment, identical challenge nonce, monotonic sequence, previous checkpoint digest, issue/expiry and explicit `HOLD`. Extra GO fields, mixed-source hashes, bad canonical key or modified signed bytes are rejected. Witness validity is bounded to maximum 15 minutes and issuance no more than 5 minutes in the future or 15 minutes earlier than the supplied verifier time.
- Checkpoint compare is **local only**: exact `sequence=previousSequence+1` plus previous digest matching separately supplied comparison pin; genesis is `sequence=0, digest=64 zeroes`. Candidate computed domain-separated **unsigned next checkpoint SHA-256** is emitted only after all internal comparisons. **No external CAS, immutable WORM checkpoint, anti-equivocation witness, durable replay detection, certified time or trusted external ledger is asserted**. An attacker controlling both input checkpoint and witness signing keys can manufacture a fully consistent but untrusted candidate.
- It reruns the full Phase 1DN in-process candidate/actual reviewer session join using the signed corporate appointment and original local evidence instead of trusting a positive but identity-redacted public receipt. Even if both of its separately pinned self-signed Legal/Registry witnesses verify, fields for independent corporate registrar, legal MCA, production CA/revocation, external WORM CAS/DR/OIDC/SLSA and Security/Legal/Ops/Owner staging authorization remain strictly **false**.
- No raw GitHub names, session key or HMAC, legal identity documents, registrar signing keys, PEM contents, witness signatures, challenge nonce or raw checkpoint manifest is exposed in operator reports. No network I/O, GitHub admin write, request review, supplier/customer dispatch, finance/inventory/tax operation, live provider activation or deployment is implemented.
