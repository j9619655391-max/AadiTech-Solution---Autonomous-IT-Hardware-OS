## A further exact-source boundary

An authenticated GitHub read-only API observation of a PR `head.sha`, `base.sha` and PR test-merge SHA is useful but **not sufficient by itself** to demonstrate that the CI worker actually checked out and tested that exact source graph. Phase 1BY adds `scripts/phase1by-pr-merge-lineage.mjs` to corroborate **the raw Git commit object** `git cat-file -p HEAD` against the **GitHub Actions original pull_request event payload** (`GITHUB_EVENT_PATH`) and `GITHUB_SHA`/actual `git rev-parse HEAD`. It deliberately checks only PR merge runs and never mutates the branch, requests new keys or performs production actions.

Required exact-source conditions: correct repository and `pull_request` event, `refs/pull/1/merge`, PR #1 open/Draft/unmerged, expected development source branch and `main` base branch, correct PR author, no fork/substituted repository, exact forty-hex-character source/base/test-merge IDs, identical `GITHUB_SHA` and checkout `HEAD`; webhook `pull_request.merge_commit_sha` is **recorded separately** because the PR event snapshot may contain a stale or missing synthetic merge SHA, and it must not veto correctly corroborated Git object ancestry. The report explicitly sets `githubEventMergeShaMatchesCheckout` / `eventMergeShaMetadataStaleOrMissing`; checked-out **Git commit object has exactly two parents**, with **first** equal to event `base.sha` and **second** equal to event `head.sha`. Git commit message content cannot masquerade as header parents because header parsing stops at first blank line. The read-only command uses fixed `git` arguments (no shell) and raw header parsing remains possible in a GitHub Actions shallow checkout without fetching full parent objects.

Any changed source/base, swapped parent order, extra/missing parent, unsupported event, fork/author/ref mismatch, invalid/oversized commit object or wrong test-merge checkout **fails the independent lineage job**. The result is the local unsigned JSON `phase1by-pr-merge-lineage-hold.json`; it explicitly reports `githubReviewRolesAuthenticated=false`, `branchProtectionServerSideVerified=false`, `signedCIExternalIdentityVerified=false`, `externalWormRetentionVerified=false`, `independentSecurityApprovalVerified=false`, `productionReleaseAuthorized=false`, `releaseDecision='HOLD'`. A green source-graph check **does not establish trusted checkout action provenance, CI attestor identity, independently retained WORM storage, valid signer enrollment, CODEOWNERS or upstream vendor remediation.**

Ten adversarial cases in `tests/phase1by-pr-merge-lineage.test.mjs` cover a valid synthetic two-parent structure, parent swaps/forged ancestry, invalid checkout/event/hash, wrong PR/author/branch/fork, malformed commit header, fake message header, no actual external approval, and shallow-object parent parsing. No real approval keys, tokens or credentials are committed.

CI includes independent read-only hosted `source-merge-lineage-hold` job only for `pull_request` events; its evidence is uploaded as **HOLD**, never an approval. The Phase 1BW policy, PR checklist and Phase 1BY live read-only observer's required status context list include the new source lineage gate. The **existing zero Critical/High dependency gate remains unchanged** and continues to block production for unresolved `picomatch@4.0.7` High severity GHSA-fc5q-39xc-vjpf.
