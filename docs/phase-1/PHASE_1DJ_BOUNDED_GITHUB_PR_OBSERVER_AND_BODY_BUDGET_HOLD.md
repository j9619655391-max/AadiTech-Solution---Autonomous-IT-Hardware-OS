## Implementation

It requires exact final GitHub endpoint URL, `redirected=false`, `application/json` or `application/*+json`, a bounded safe numeric `content-length` when provided, an actual readable stream, bounded chunks and fatal UTF-8 decoding. Overlength declared or received bytes return explicit `oversize`; malformed header, MIME, URL, stream or JSON returns `invalid`; HTTP 403 stays `access_denied`, never construed as no effective rule. The preexisting fixed path allowlist, GET only, six-and-a-half-second timeout, no secret output and failure-safe governance remain intact. No `response.text()` fallback.

The same observer now computes UTF-8 **byte length**, not JS character count, of the official PR #1 description and marks `BY_PR_DESCRIPTION_OUTSIDE_BOUNDED_EVIDENCE_INDEX` if missing/malformed or above **8,192 bytes**. Its existing `--ci-hold` action fails only for this PR-body-budget breach (or earlier prohibited production-GO violations), without demanding external corporate roles as a prerequisite for normal internal HOLD CI.
