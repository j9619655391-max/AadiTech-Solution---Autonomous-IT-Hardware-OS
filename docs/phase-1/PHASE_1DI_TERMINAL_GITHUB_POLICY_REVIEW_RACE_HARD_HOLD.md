## Real preflight race fixed

Phase 1DG independently reads all three CODEOWNERS paths twice at an immutable base-`main` SHA, after a Phase 1DF role-specific reviewer reconciliation. Yet, until this phase, its human-only command **did not re-check** current PR source/base HEAD, submitted reviewer decisions, or active rulesets **after** the CODEOWNERS calls. An administrator could change `main` or a GitHub reviewer could dismiss an approval during that read window. Also, Phase 1DC previously returned aggregate rule counts, meaning a bypass actor or ruleset detail swap with the same number of rules could evade a count-only comparison.

## Implementation

- `scripts/phase1dc-live-external-governance-readiness.mjs`: adds exported `digestGithubMainPolicyReadbacks`, returning only a domain-separated **unsigned SHA-256 fingerprint** of the bounded official GET readback projection of **all** repository ruleset listings, their details (including bypass actors), all three CODEOWNERS path records and the direct main branch-protection response. This fingerprint reflects changes to policy contents even when counts match. It is not an external signature, signed GitHub attestation, proof of continuous compliance, or an independent admin identity.
- `scripts/phase1di-terminal-main-review-recheck.mjs`: pure `assessTerminalReadOnlyMainAndReviewRecheck` now binds **four** official 1DC main/PR/policy snapshots (the two initial readbacks and two terminal readbacks), a completed 1DF two-role current-HEAD join, a completed 1DG pinned effective CODEOWNERS receipt, and **one fresh actual nominated 1CO review read**. All source HEADs and base-`main` SHAs must equal the original, all four complete official readbacks must maintain strict verified code owner coverage, actual active main no-bypass rule readbacks, readable main protection and zero source anomalies. The complete unsigned policy fingerprint and all submitted/current-head counts must be identical across all four. Terminal named Security and Business technical approvals and repository permissions must be observed against the same HEAD; submission/approval totals must agree with the official GitHub 1DC counts.
- `scripts/phase1dg-effective-codeowners.mjs`: its explicitly human-run, GET-only `--inspect-pinned-main-codeowners-readonly` CLI now performs **after** the two CODEOWNERS reads: `collectLiveActualGovernance` → `collectLiveReviewerEvidence` for **the same two operator-supplied nominees** → `collectLiveActualGovernance`. The output includes a separate 1DI boolean/anomaly technical receipt with **no logins, token or raw policy/review records**, and returns a nonzero operator status if this final consistency check fails. It does not install rulesets or authorize a protected branch change.
- `tests/phase1di-terminal-main-review-recheck.test.mjs`: **22 Node adversarial groups**, including terminal HEAD/branch drift, dismissal and subsequent review mismatch, same-count ruleset/bypass swap digest change, CODEOWNERS content change, protection toggle, missing inputs and 403 UNKNOWN, mismatched official vs named approvals, malformed unsigned digest, API source spoof and permanent HOLD even when all mocked technical fields are positive. ## Explicit limitations / security statement

This is repeated polling of GitHub's official GET endpoints, **not** an atomic multi-resource transaction or cryptographically signed external witness. A policy or review can be altered **after** the final read; equal fingerprints cannot prove that no temporary edit-and-revert occurred between reads or guarantee protection against a compromised GitHub account. A synthetically passing unit fixture is not a real corporate mandate. Real reviewer usernames or token are not requested or stored in repository, CI or chat. All external legal/CA/WORM evidence remains unprovided. The human-only CLI must not run without separately appointed and independently authenticated nonauthor corporate Security and Business officers and approved read-scoped `GITHUB_READ_TOKEN` from a secrets manager.
