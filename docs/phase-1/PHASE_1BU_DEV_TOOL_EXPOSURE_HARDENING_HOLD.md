## Why this is required

Phase 1BT moved Vite and related plugins out of the production dependency graph; real `bun install --production --frozen-lockfile` found no `picomatch`/Vite under production-only `node_modules`. But a vulnerable developer glob tool remains installed in full development and CI environments. The runtime `NODE_ENV !== 'production'` route still initialized Vite middleware, and nonproduction `resolveDeploymentSecurity` formerly accepted any `APP_BIND_HOST`. Running that configuration in a publicly reachable dev/staging network or trusting DNS rebinding or forged `Host`/`Origin` creates avoidable attack-surface risk even though production dependency containment succeeded.

As independently checked on **18 November 2026 (IST)**, GitHub [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) / CVE-2026-112366 still describes the High-severity `picomatch` repeated single-branch-extglob ReDoS through `4.0.7` with no verified fixed release; npm [picomatch versions](https://www.npmjs.com/package/picomatch?activeTab=versions) still show latest `4.0.7`. A dev-server host/IP restriction is **containment, not a fix to the vulnerable matcher**.

## Implemented internal fail-closed engineering

1. `server/security/devToolExposure.ts` adds `resolveDevToolExposure(env,port)`, a pure startup gate: only `NODE_ENV` absent, `development` or disposable `test`; literal bind address `127.0.0.1` or `::1`; exact integer TCP port. It rejects wildcard/LAN/public binds (`0.0.0.0`, `::`, `192.168.x.x`, `localhost` hostname aliases for bind), mixed `HOST`/`VITE_HOST` overrides, `APP_ALLOW_PUBLIC_BIND=true`, `DEV_SERVER_PUBLIC=true`, arbitrary Vite additional allowed hosts, typo `NODE_ENV` values. `production` cannot enter the dev resolver. Explicit outputs never assert patched `picomatch`, approved security, production or real provider authority.
2. `server/security/deploymentGuards.ts` invokes this gate for **all nonproduction process configurations** before the listener is created or Vite dynamically imported. Production TLS/reverse-proxy/DB/MFA settings remain enforced separately. An independently approved external staging environment must use a secured production-style static build and independent authority processes; exposing developer tooling to public/staging clients is not allowed as a workaround.
3. `server.ts` places `devToolHostGate` before every Express route and Vite middleware in dev/test. It strictly accepts local `Host` endpoints (including exact port), any `Origin` must match its exact local Host, and blocks conflicting/foreign `Host`, `Origin: null`, DNS-rebinding hosts, `Forwarded`, `X-Forwarded-Host`, `X-Original-Host`, `X-Forwarded-For` and `X-Forwarded-Proto`. A denial returns HTTP 403 with no side effect. Dev responses use no-store cache headers and `nosniff`. It does **not** trust client-supplied proxy headers to override the binding or origin.
4. `server.ts` also initializes Vite middleware with explicit `host: 127.0.0.1`, restricted allowed hosts, `cors: false`, `strictPort: true`, `hmr: false`; it still loads Vite dynamically **only** on the nonproduction path.
5. `vite.config.ts` constrains both standalone Vite **dev** and **preview** to loopback binding, localhost/127.0.0.1 allowed hosts, strict ports and `cors:false`; dev HMR disabled and filesystem confinement `fs.strict:true`. Local-only tooling is intentionally less convenient than permissive development defaults. This does **not** prevent a privileged operator from deliberately modifying files or invoking Vite CLI with unsafe flags; such actions must remain denied by independent deployment controls.
6. `tests/phase1bu-dev-exposure.test.ts` runs real ephemeral HTTP requests on 127.0.0.1 to verify successful localhost traffic and denial for malicious Host, subdomain spoofing, Origin, cross-localhost alias, forwarded IP/proto and Vite route access; pure tests verify non-loopback listener, port validation, unsafe overrides, NODE_ENV typo rejection, production HOLD and static Vite server/preview config. Existing `tests/deployment-guards.test.ts` production HTTPS/proxy/MFA checks remain required. No external Internet/DNS is queried by these tests.
7. `.github/workflows/ci.yml` runs actual **curl-based malicious Host/Origin/forwarded-header requests** against the real loopback Express+Vite app immediately before the existing **Chromium privileged-MFA/role browser smoke**, requiring HTTP 403 for all. The original browser smoke remains mandatory; no mock or skip. Earlier `production-runtime-scope` isolated frozen Bun production dependency job also remains.
8. This phase does **not** change the production/CI `bun.lock` vulnerable version or soften `scripts/verify-patched-dependencies.mjs`. The global **zero Critical/High** baseline gate is mandatory. `docs/security/dependency-advisory-baseline.json` still marks the High alert **known unresolved development-only**, with independent Security approval pending. A green local-Host test or production package graph cannot authorize release.
