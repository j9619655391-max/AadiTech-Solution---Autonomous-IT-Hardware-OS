## Objective and nonnegotiable trust boundary

Phases 1CE–1CF check bounded, *caller-supplied* witness and two-epoch checkpoint history, Merkle tree arithmetic, and latest-head signed candidate reviews. Phase 1CG checks extra **prerequisites** for independent source corroboration: two purported external data-retrieval channels with independently keyed publication statements, optimistic atomic checkpoint compare-and-swap (CAS) context, fork gossip and source-bound *read-only* GitHub reviewer observation. It **does not** perform actual external retrieval, prove HTTPS/TLS peer identity, authenticate signer key enrollment, create persistent storage, enforce a cloud CAS transaction, authenticate official GitHub reviewer roles, or release to production.

The only current operational runtime path is `--ci-hold`, which has **zero external data, zero actual source endpoints and no secrets**. Tests use local synthetic Ed25519 private keys with **reserved illustrative hosts** `publisher.example.org` and `witness.example.net`. Those endpoints are not enrolled production authorities and must be replaced with approved separately administered sources before any genuine onboarding; merely changing the strings cannot confer trust.

## Implemented code and checks

`scripts/phase1cg-external-source-reconciliation-preflight.mjs` exports `publicationBytes` and `assessExternalSourceReconciliation`. Its strict schema and domain-separated payload logic enforces:

1. **Source and CI envelope:** Requires an untampered Phase 1CC unsigned source receipt with SHA-256 digest, exact checked-out PR test-merge SHA, source development HEAD, repository, branch and release HOLD state. Candidate publication binds the same CI run ID, attempt, independent nonce, immutable archive version and archived envelope SHA-256.
2. **Monotonic high-watermark / optimistic CAS:** Requires supplied persisted source anchor (`storeId`, old `version`, `epoch`, prior publication SHA-256, Merkle size/root), then a precisely one-version/one-epoch successor. The signed successor includes **old tree size and root** and rejects rollback, same-size conflicting roots, reused publication digests when growing, missing predecessor, stale/future epochs, tampered source or archive. **There is no persistent CAS service or independent high-watermark in this phase**; supplied source-state checks can only detect conflicts inside the packet, not rewrite-resistant cross-run trust.
3. **Two source-signed candidate observations:** Distinct `PUBLISHER_OBSERVER` and `INDEPENDENT_WITNESS_OBSERVER` keys and roles, organizations, administrator references and logins. Explicit Ed25519 public key SPKI pin, supplied non-revocation and validity dates, domain-separated signed publication digest, old source anchor digest/version, new version, run-bound nonce and issuer role. Signed observation must claim HTTP 200, zero redirects, expected endpoint host and a SHA-256 fingerprint for the claimed TLS peer. **The TLS/HTTP observation is just caller-supplied data, not authenticated transport.** Fabricated independent organizations cannot become real authority.
4. **Fork gossip:** Up to eight bounded candidate alternate log states. Different digests for an already expected epoch, or a higher observed epoch, result in a fail-closed fork/advanced-state anomaly. Actual cross-organization independent monitoring and immutable dissemination are **not** created here.
5. **GitHub PR and reviewer evidence:** A supplied Phase 1BY-shaped read-only observation must correlate the same PR, source HEAD, synthetic test-merge SHA and claimed protection state and keep independent-authentication flags **false**. The candidate reviewer event history supports at most 200 bounded events, latest-submitted-state wins (id tie-break), and requires two distinct non-author claimed Security and Business reviewer identities, `APPROVED` state on the **exact current source SHA**, and approval submitted **after the last source push**, with their logins present in the alleged official observer's approved-login set. Rejected/dismissed/revoked prior reviews, missing role quorum, stale SHA and fake GO are rejected relative to the supplied data. **This is not the official live GitHub API review, membership/role proof, enforced CODEOWNERS/ruleset, signed Security or business acceptance.** A separately authenticated GitHub source and independent Security/business identity mapping are necessary.
6. **CI no-trust bridge:** After BV/BZ/CC/CD/CE/CF, the existing `build-input-provenance` job executes `node scripts/phase1cg-external-source-reconciliation-preflight.mjs --ci-hold`. It accepts no arbitrary external inputs; verifies the local Phase 1CC receipt, Phase 1CF held zero-input report and actual GitHub job/checkout context; emits `phase1cg-zero-input-external-reconciliation-hold.json`. The existing uploader archives a **seventh UNSIGNED local evidence report**. No ninth CI job, new action/tag, permission increase, secrets, outbound provider calls or release side effects. Phase 1BV and Phase 1BW source input inventories now hash both the CG script and tests.

`tests/phase1cg-external-source-reconciliation-preflight.test.mjs` adds 14 adversarial Node test groups: mathematically valid *synthetic* dual-source Ed25519 and two fabricated reviewer events (never trusted outside source), missing/zero input, epoch CAS rollback and wrong old root, run/archive/nonce spoof, signed digest mismatch, fake TLS fingerprint/redirect/HTTP state/endpoint, swapped or revoked keys, common source administrators, conflicting fork gossip/high-watermarks, fake Phase 1BY status, stale/dismissed/old-head/post-push reviewer decisions, shared reviewer assignments and extra self-proclaimed GO.
