## Why this phase is needed

Phase 1BQ checks a registrar-signed candidate enrollment manifest and two separately signed **offline** candidate collector captures. It compares claimed TLS SPKI, CRL/OCSP digest, WORM denied-delete and encrypted-restore head, **without examining the underlying bytes or verifying an actual remote TLS session**. Hash consistency within a synthetic packet is not externally authenticated evidence.

Phase 1BR implements **byte-level offline cryptographic preflight** and an independently configured **candidate X.509 trust-root fingerprint**. The checkpoint is signed by a temporary provider-test leaf private key whose certificate chains directly to a separately supplied (and SHA-256 pinned) root. The checks establish only **local cryptographic consistency of supplied bytes and configured test key**. They never establish a real authorized eMudhra/CCA/RCAI trust root, X.509 CPS/certificate-policy path, actual provider endpoint, live signed CRL/OCSP, legally authentic provider identity, cloud Object Lock, or witnessed disaster recovery.

## Implemented controls

1. `server/commercialIntegrity/quoteProviderBytes.ts`: exact-field `aaditech-quote-provider-byte-evidence-v1` envelope containing bounded canonical base64 for a signed original UTF-8 checkpoint, one leaf PEM certificate, separate root PEM provided outside the evidence packet, bounded CRL and OCSP DER blobs, WORM claim bytes and DR transcript bytes. JSON must be encoded in canonical no-whitespace serialized form, with no additional fields, and base64 is round-trip canonicalized. DER parsing is **only a bounded, definite-length outer SEQUENCE check**; it does not parse/verify RFC 5280 CRL/OCSP structures or their responder signatures. The application must never treat this weak structural check as revocation verification.
2. The `createVerify('RSA-SHA256')` preflight checks the original checkpoint bytes with domain separation, using the supplied leaf certificate public key. `node:crypto.X509Certificate` checks candidate root self-signature/CA bit, leaf issuer signature against that root, leaf not marked CA, expected provider hostname and both certificate validity windows. The root certificate **never comes from the uploader packet**, and the root's DER SHA-256 must equal the independently configured `BR_ROOT_CERT_SHA256`. The hostname is separately configured as `BR_PROVIDER_ORIGIN`, not taken on trust from the evidence blob. This limited offline one-hop check does **not** validate actual chain trust, key usages/CPS/revocation, trusted time, multi-intermediate chain, real TLS session or legally authorized provider control.
3. The leaf-signed checkpoint binds original quote ID, unique BQ challenge, stored BQ packet SHA-256, signed-candidate BM receipt, source SHA-256 and monotonic sequence/epoch, narrow freshness/expiry, and raw CRL, OCSP, WORM and DR blob SHA-256. The BQ packet must hash exactly to the **stored prior BQ stream HEAD**; both prior collector captures must agree with each other and this checkpoint's head, revocation and CRL/OCSP digests. A fabricated signed payload pointing at an unrelated BQ packet cannot pass.
4. The WORM bytes must carry the same held quote ID, synthetic object ID, claimed denied overwrite/delete and future retention date as the signed BQ capture. The DR bytes must carry the same source, receipt, sequence, distinct operator/witness IDs and bounded claimed RTO/RPO; rollback, fork, stale simulated drill and mismatched blob hashes are rejected. `SIMULATED_ONLY` is the **only** permitted WORM/DR evidence state; no genuine independent WORM or encrypted restore is claimed.
5. `database/migrations/0041_br_provider_byte_evidence.sql` adds an FK-linked local BR candidate stream and bounded audit attempts to the BQ head. All fields claiming independently authenticated provider root, live TLS, issuer path, signed CRL/OCSP, WORM and real DR are physically restricted to MySQL `ENUM('NO')` and `production_release` to `ENUM('HOLD')`. Plain MySQL remains mutable by privileged administrators and is not independent WORM storage.
6. `server/commercialIntegrity/quoteByteCustody.ts`: isolated/disposable-MySQL transaction locks the quote source and complete BM→BN→BO→BP→BQ lineage, recalculates upstream consistency, pins the separately configured candidate root certificate digest and provider HTTPS origin, verifies all raw bytes, records only packet SHA/issuer candidate digest and claimed revocation epoch, enforces strict predecessor/sequence, accepts idempotent **exact latest** replay, and makes different-BQ/same-head, root rollover, revocation regression, source drift, signed evidence conflicts or stored ledger tampering sticky **QUARANTINED**. A changed encrypted WORM/DR or CRL/OCSP blob cannot silently satisfy a prior hash.
7. `scripts/migrate-br-provider-bytes.ts` checksum-verifies all **40** predecessor SQL migrations under the existing exclusive migration mutex; idempotent #0041 registration. Writes and migration refuse production, permitting disposable CI only, or explicitly approved disposable TLS staging with all BM/BN/BO/BP/BQ prerequisites plus `BR_BYTE_INTAKE_APPROVED=YES`. Actual BR byte recording additionally requires configured `BR_ROOT_CERT_SHA256` and `BR_PROVIDER_ORIGIN`. No provider passwords/private keys are stored in chat or repository, and no public API allows BR dossier writes.
8. Existing `OWNER`-only, privileged-MFA `GET /api/commercial-integrity/quotes/:id` remains inspection-only and reports BR local candidate ledger integrity alongside BM/BN/BO/BP/BQ. No release, real quotation issuance, vendor PO dispatch, GRN, stock, finance/tax action or production deployment.
9. `tests/br-provider-byte-evidence.test.ts` and `tests/br-provider-bytes-mysql.integration.ts` generate **ephemeral synthetic root+leaf RSA X.509 keys and certificates** via OpenSSL in a disposable temp directory (never checked in), sign checkpoint bytes, then test SHA/canonical base64/DER swaps, wrong root/host, forged signature, WORM/DR rollback, BQ predecessor mismatch, live MySQL local ledger tampering and quote source drift. CI runs migration #0041 before owner quote integrity smoke and BR data-mutating tests after the older suites. Both baseline and MySQL workflows, Chromium MFA smoke, manifest checksum and the complete M01–M30 register remain mandatory.

- A legally approved **named** provider agreement authorizing precisely this application's test/production environment, independently verified provider/CA organizational identity, RCAI/CCA/eMudhra certificate hierarchy and certificate-policy/OID constraints.
- A root store and authorized registrar **enrolled out of band**, with independent custodian approvals, HSM custody, key rotation/revocation governance, root pin versioning and audit transparency—not a test fixture, uploader-provided PEM or environment variable controlled by the applicant.
- A **real network client** with allowlisted DNS/IP resolution, no redirects, egress isolation, mTLS as approved, TLS certificate pinning validated against the actual session and independently retrieved signed checkpoint head. Persist the monotonic head in independent append-only/WORM storage controlled by a different authority. Neither phase 1BQ nor 1BR has made an external HTTP request.
- Full RFC-compliant X.509 chain/path validation and **actual signed live CRL/OCSP** parsing/signature/responder permission/nonce/freshness/serial and no-rollback verification. Here, CRL/OCSP are **fake DER test fixtures** whose bytes are hashed; no status authenticity is established.
