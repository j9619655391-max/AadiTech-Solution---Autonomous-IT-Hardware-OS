## Implemented controls

1. `server/commercialIntegrity/quoteAnchors.ts` introduces `buildLocalQuoteHistoryCommitment`. It reads explicit source fields from the original draft, the ordered initial items, all internal quote revisions with line snapshots, per-version reviewer decisions, held release snapshots and disabled outbox status. It canonicalizes JSON object keys, handles MySQL JSON columns as objects or strings, includes source value changes in one domain-separated SHA-256 digest (`aaditech/quote/history/source/v1`). Malformed JSON, unknown/unsupported runtime scalar types, nonfinite numbers, invalid or duplicate version numbers and out-of-bounds history **throw / fail closed**. For source-of-truth readback it does **not** accept a supplied hash, claimed approved signer, address or quote amount.
2. Owner-scoped `GET /api/commercial-integrity/quotes/:id` (existing privileged MFA and transactional quote parent lock) returns `localHistoryCommitmentSha256`, `localHistoryCommitmentFormat`, `localHistoryCommitmentExternallyPublished=false`, `authenticatedWitnessCheckpointAvailable=false`, `independentlyAuthenticatedRevocationAvailable=false`. It returns null for the digest on truncated sources. The root is computed from the already inspected MySQL source rows, not a browser parameter, and does not enable issuance, authority, dispatch or update operations.
3. The **offline-only**, pure `verifyCandidateQuoteWitnessChain` verifies Ed25519 detached signatures over canonical exact-key witness payloads, a source digest and quote ID, strictly increasing sequence numbers, receipt-hash predecessor links, nondecreasing revision numbers and increasing explicit UTC timestamps; all signing pins must be **supplied out of band**. Pinned key IDs must be distinct, well-formed and marked ACTIVE; REVOKED/UNKNOWN/absent/unpinned/replaced/invalid-window pins fail closed. Unknown metadata, wrong quote, cross-signed payload, broken predecessor, replayed/stale versions, malformed signature and stale source-head checks fail. The per-receipt hash is domain separated (`aaditech/quote/history/receipt/v1`). There is a 32-receipt bound; source histories are limited to 1000 revisions.
4. The verifier is **not exposed via HTTP** and **does not install key material or mark independent authorization true**, even if a synthetic Ed25519 fixture signs successfully. A candidate chain can be cryptographically consistent, while `independentWitnessAuthorityAuthenticated=false`, `independentWitnessRevocationAuthenticated=false`, `independentlyPublishedHeadVerified=false`, `independentRollbackProofVerified=false` and `productionReleaseAuthorized=false` always. The verifier does **not** independently resolve a genuine key owner's identity, authenticate a remote time server, fetch OCSP/CRL, retain a trusted external monotonic latest-head record, publish a legal source-of-truth or prove an out-of-band pin was actually authorized.
5. Regression tests: `tests/bl-quote-anchors.test.ts` covers deterministic equivalent MySQL JSON formats, internal source state mutation, overwritten historical outbox, forged reviewer, HSN and money, synthetic Ed25519 key rotation, revoked/unknown/unpinned key, forged signature, lost predecessor, replay, stale head, malformed packet, bounds and explicit no-production authority. The original `tests/crm-mysql.integration.ts` Phase 1BK database mutation/restore test now requires local root changes for old held-snapshot tamper, revision tax drift and revision-number rollback, and exact root restoration after database restoration. No mock replacing actual MySQL integration.
6. **No migrations**, signing private keys, new user permissions, live witness/provider endpoint, WORM publication, inventory receipts, customer quote issue, supplier PO send, accounting entry, stock posting or external business operation.

## Acceptance / independent provenance requirements not met

Before even evaluating trusted witness acceptance, a legally approved provider agreement and independently authenticated organization/issuer names; a jointly authorized pin-enrollment change-control dossier; hardware-vault-backed signing key custody; independently checked CRL/OCSP/revocation-feed identity and freshness; immutable provider signed monotonic log heads and authenticated receipt-of-publication; and separately witnessed encrypted DR + restoration/rollback exercise are required. The trusted published predecessor and successor **must be retained outside the applicant's MySQL and GitHub repository** and should be corroborated by independently operated witnesses; a signed packet provided by the applicant is insufficient. If a key is suspected, compromised, revoked, expired or replaced, the release gate stays frozen, with independent incident and revocation checks before any subsequent approval.

Even a cryptographically correct chain **cannot detect the deletion of an internally consistent tail** unless a separately authenticated published head from before the rollback is available. Likewise the current source is still applicant-managed; no independently verified company/customer/supplier legal records, SKU/HSN/GST supplier quotes, CCA/eMudhra trust chain or production signer authority are claimed. This phase is a **prerequisite**, not external onboarding or full acceptance.
