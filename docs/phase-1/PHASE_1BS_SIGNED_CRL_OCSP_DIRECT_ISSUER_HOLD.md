## Context and deliberately limited trust

Phase 1BR can verify a synthetic provider checkpoint's leaf X.509 signature and bind bytes of alleged CRL/OCSP, but it does **not** validate CRL/OCSP issuer cryptographic signatures, certificate serial revocation or responder nonces. Phase 1BS adds a *strict, intentionally narrow* offline ASN.1 DER and crypto verifier for an **issuer-direct, pinned synthetic RSA-SHA256 candidate root**. A locally configured SHA-256 thumbprint and matching CRL/OCSP signatures do not prove that this root is an actual RCAI/CCA/eMudhra authorized provider or independently administered CA. A real live OCSP request was not sent. This does not authorize quote issuance, purchasing, stock, accounting or production deployment.

## Engineering delivered

- `server/commercialIntegrity/quoteSignedDer.ts`: bounded definite-length ASN.1 DER reader with length/tag/children/canonical integer/OID/GeneralizedTime/UTCTime/BIT STRING/algorithm/extension checks. Nonminimal, indefinite, oversized, trailing, duplicate or unsupported structures fail closed. Extracts issuer X.509 subject/key bytes and target certificate serial for signature/revocation checks. Not a universal RFC 5280 or RFC 6960 parser; unknown/delegated certificate paths are rejected.
- `server/commercialIntegrity/quoteSignedRevocation.ts`: accepts the exact prior **BR original byte packet** matching the current locally held BR SHA and an *out-of-packet* candidate issuer PEM whose DER digest must equal independently configured `BS_ISSUER_ROOT_SHA256` **and** the BR recorded candidate root SHA. The issuer CA certificate and test leaf must form a self-signed candidate root/one-hop X.509 signature relationship and be in their validity period. The verifier restricts CRL and OCSP response signatures to **RSA-SHA256** under that direct candidate issuer key; any unauthorized delegation is rejected.
- For a **v2 signed CRL**: verifies DER `CertificateList` signature over the original `TBSCertList` bytes, matching root issuer name, `thisUpdate`/`nextUpdate` strict fresh UTC values, issuer-signed `cRLNumber` extension and minimum monotonic epoch. Exact quote leaf serial in the signed revoked-certificate list is an immediate HOLD. Duplicate revoked entries, negative/oversize serials, stale/future time or old CRL Number fail closed.
- For a **successful signed OCSP BasicResponse**: validates signed original `ResponseData` via the directly pinned issuer RSA key, issuer-by-name responder identity, exactly one `SingleResponse`, leaf certificate's exact DER serial and SHA-1/SHA-256 issuer name/key identifiers, **good** status (revoked/unknown are blocked), `producedAt`, `thisUpdate`, mandatory `nextUpdate`, and a signed OCSP response nonce equal to bytes of the locally bound server-issued BQ challenge SHA. Missing, replayed or changed nonce fails closed. Delegated responder certs, byKey responder IDs, OCSP request networking and unfamiliar algorithms are **not supported** and remain fail closed.
- `database/migrations/0042_bs_signed_revocation_holds.sql`: local FK-bound BS stream and immutable-shaped attempt chain (though plain MySQL is not external WORM). Enforces real independently enrolled CA, real CRL distribution, live authorized OCSP response and independently retained revocation head flags to **`ENUM('NO')`**; production release **`ENUM('HOLD')`**.
- `server/commercialIntegrity/quoteRevocationCustody.ts`: transaction locks original quote/source and BM→BN→BO→BP→BQ→BR state; compares exact BR byte packet digest, pinned candidate root, signed CRL Number, and real status expiry. Signature-invalid packets are never inserted; verified negative status, serial mismatch, bad nonce, stale status, epoch rollback, repeated BR candidate evidence or upstream drift are quarantined. A valid exact latest replay is idempotent. OWNER-only privileged MFA quote GET now includes BS head/revocation freshness and ledger consistency anomalies, with no external mutation endpoint.
- `scripts/migrate-bs-signed-revocation.ts` enforces advisory mutex, SHA checksums of previous **41** migrations and repeat-safe idempotent `0042` schema registration on disposable CI or separately approved isolated TLS staging. Staging must meet all earlier BM/BN/BO/BP/BQ/BR opt-ins **plus `BS_SIGNED_REVOCATION_WRITE_APPROVED=YES`**; actual recording also requires separately configured `BS_ISSUER_ROOT_SHA256`. Never store real provider secrets or authorization tokens in Git.
- `tests/bs-revocation-fixtures.ts` builds actual syntactically signed CRL v2 and OCSP BasicResponse ASN.1 DER using **ephemeral OpenSSL-generated, synthetic CA and leaf RSA keys**; hashes are then re-bound into both BQ collector signatures and BR provider checkpoint signature. Unit `tests/bs-signed-revocation.test.ts` tests issuer signature forgery **with matching applicant-controlled hashes**, revoked target serial, unknown/revoked OCSP status, serial/name hash mismatch, bad nonce, CRL epoch rollback, stale/future response, spoofed issuer and BR predecessor.
- `tests/bs-signed-revocation-mysql.integration.ts`: real disposable MySQL tests the full candidate BM→BN→BO→BP→BQ→BR chain, signed CRL and OCSP status processing, pin substitution rejection, exact replay, negative status quarantine, forged signature zero-write, signed stale status, stored head mutation, BR predecessor and original HSN quote-source tampering.
