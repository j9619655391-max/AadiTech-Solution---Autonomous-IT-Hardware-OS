# Phase 1DK — Complete submitted-review decision-history digest and four-read drift check

**Date:** 20 November 2026 IST. **Repository:** `j9619655391-max/AadiTech-Solution---Autonomous-IT-Hardware-OS`. **Development branch:** `chore/phase0-foundation-20261106`. Neither `main` nor production is modified.

## Concrete source-consistency flaw

Phase 1DI compares two initial and two terminal official GitHub governance readbacks before/after pinned `main` CODEOWNERS file verification, including full-policy source digests and **aggregate submitted-review and current-head approval counts**. It does **not** hash full GitHub review decision records. A third, unrelated review can change from `COMMENTED` to `DISMISSED`, or its commit, submission timestamp, user or review ID can change while **both** aggregate counts remain unchanged. The existing 1DF and 1CO nominated Security+Business latest-head checks can still pass, but the 1DI technical receipt may claim stability across all four official reads despite the review history having changed. This phase closes that bounded source-consistency gap, not a legal delegation gap.

## Technical implementation

- New `scripts/phase1dk-submitted-review-history-integrity.mjs` provides pure `digestOfficialSubmittedReviewHistory`. It accepts ONLY a complete `status=read,complete=true` official submitted-review pagination envelope at a known exact 40-hex current PR source SHA; maximum **299 records**. It reuses the actual strict `evaluateLatestSubmittedReviews` review validation from Phase 1CO. It sorts all review rows by immutable GitHub review ID and hashes a deterministic, domain-separated projection of **review ID, lowercased GitHub login, state, commit SHA or null and submission timestamp or null** together with exact source HEAD. All review states, including `PENDING`, are represented. It rejects duplicate IDs, malformed state/login/date/SHA, invalid head, incomplete pagination and oversized projection. Raw body text is not included, nor are names/tokens or review records printed in the digest receipt. This is **unsigned SHA-256**, not an independent witness or anonymization guarantee.
- `scripts/phase1dc-live-external-governance-readiness.mjs` adds `unsignedSubmittedReviewHistorySha256` to its existing real official read-only technical summary. A missing/invalid full decision-history digest causes an explicit `DC_COMPLETE_GITHUB_REVIEW_HISTORY_FINGERPRINT_UNAVAILABLE` and preserves production HOLD. It continues to report independent policy fingerprint, exact PR and `main` source, reviewed CODEOWNERS precedence, current-head quorum and protection status without any write calls.
- `scripts/phase1di-terminal-main-review-recheck.mjs` **requires all four official 1DC readbacks** to provide a well-formed review-history SHA-256 and to agree. A changed or unreadable digest yields `DK_OFFICIAL_SUBMITTED_REVIEW_HISTORY_CHANGED_OR_UNREADABLE`, `reviewDecisionHistoryFingerprintStableAcrossFourReadsOnly=false`, and `wholeOperatorReadWindowTechnicallyConsistentOnly=false`. No PR reviews, reviewer permission, effective GitHub `main` rules or corporate mandates can be inferred from digest stability alone. The existing human-only 1DG CLI automatically uses the 1DI terminal join, so the new check is enforced for genuine authorized operator invocations without adding a secret-bearing CLI.
- `tests/phase1dk-submitted-review-history-integrity.test.mjs` has **28 adversarial Node test groups**: equal-count `COMMENTED`→`DISMISSED`, changed commit/timestamp/login/ID, added `PENDING` row, case-insensitive login and order normalization, corrupted/duplicate/unknown records, incomplete pagination, invalid head, overlong history, successful real 1DC report digest without authority, and all four possible 1DI change positions with a synthetic stable exact-main/nominee fixture. Prior `tests/phase1di-terminal-main-review-recheck.test.mjs` gains the newly mandatory review-history fixture. New script/test and modified 1DC/1DI tests are entered in Phase 1BV and 1BW custody inventories. No workflow permission changes, GitHub reviewer requests or main-rule changes.

## Non-goals, limitations, operator requirements

Four official GitHub GET observations and a stable SHA-256 **are not an atomic transaction** and cannot rule out edit-and-revert between reads or subsequent changes, compromised GitHub admins or real external role spoofing. Hash projection does not contain a provider-signed integrity proof or independent immutable WORM custody. Synthetic fixtures are used for adversarial engineering, **not** appointed corporate officers. In particular, even a positive synthetic 1DK technical receipt returns `productionReleaseAuthorized=false`, `productionReleaseBlocked=true` and `releaseDecision=HOLD`. Real legal Security and Business appointments and authentic write-scope GitHub reviewer permissions must be verified by an independent authorized human operator before running the opt-in read-only actual nominee CLI; credentials from a secrets manager only, never chat, docs, logs or Git.

At phase start, actual GitHub readbacks are still **zero submitted PR reviews; zero listed rulesets; all three standard `main` CODEOWNERS locations 404; `main` branch-protection direct GET 403 = UNKNOWN, not proved disabled**. Missing independent external gates: genuine MCA company/authorized signatory and approved eMudhra/RCAI/CCA provider contract with trusted CPS and signed live CRL/OCSP; external WORM/CAS/DR, independently signed OIDC/SLSA and staging Security/Legal/Ops/Owner approvals. The code cannot supply these authorities.
