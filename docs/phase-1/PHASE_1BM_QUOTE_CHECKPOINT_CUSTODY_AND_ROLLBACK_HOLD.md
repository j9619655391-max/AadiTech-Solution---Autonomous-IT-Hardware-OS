## Gap and non-negotiable scope

Phase 1BL provided deterministic internal quote-history SHA-256 commitments and an offline Ed25519 *candidate* witness checker. It did not persist quote-specific candidate witness heads, protect a previous internal head against conflicting submissions in a transaction, or react to a claimed revocation, stale witness head, local quotation state change, or mismatched claimed publication checkpoint. Phase 1BM adds guarded **local/durable MySQL candidate custody** and incident quarantine on that specific internal evidence path. It does not connect to a real external witness, validate genuine eMudhra/CCA issuer or provider credentials, create a trusted monotonic publication, prove independent revocation, or deliver a quote.

## Engineering

- `database/migrations/0036_bm_quote_candidate_checkpoints.sql` defines `quote_bm_candidate_checkpoint_streams` and append-attempt `quote_bm_candidate_checkpoint_attempts`, both FK-bound to an existing quote, with immutable **enum schema bounds** for `NO` external authority and `HOLD` release. Stores last candidate sequence, source commitment, signed receipt hash, revision number and candidate pinset hash. Attempts record accepted internal candidates and incidents with a never-upgrading quarantine state. This is ordinary MySQL, **not external WORM**.
- `scripts/migrate-bm-quote-checkpoints.ts` uses the migration advisory mutex, complete `MIGRATIONS` history and SHA-256 checksum, disallows unknown/changed schemas and performs a safe idempotent rerun. `bmQuoteCheckpointWriteTarget` rejects production and unapproved or non-TLS staging. Only `NODE_ENV=test`, `CRM_TEST_DB=1`, `DB_NAME=aaditech_ci`, or explicitly approved disposable isolated TLS staging with `BM_QUOTE_WRITE_APPROVED=YES` may mutate the candidate-only tables. Never set these flags on real production.
- `server/commercialIntegrity/quoteCheckpointCustody.ts` provides **non-HTTP** `recordCandidateQuoteCheckpoint`. It verifies the Phase 1BL full signed-candidate prefix and exact source head, then locks the actual quote parent row in MySQL and re-computes the original/revisions/review/holds/outbox commitment from server-owned rows. Existing source/history scope must be consistent for acceptance. A per-quote locked candidate stream serializes concurrency; duplicate exact replay is idempotent. Sequence gap, fork, rollback, mismatched predecessor, unreviewed source drift, candidate key-pin change, mismatched claimed publication head and revoked/unknown candidate pin are denied/quarantined. A signed *claim* of key revocation can cause sticky local freeze **without** being mistaken for externally published CRL/OCSP.
- `inspectCandidateQuoteCheckpointOnConnection` recomputes **persisted candidate head vs accepted attempt history**, sequential receipt hashes, recorded pin set, candidate revision numbers, governance state, changed current source and forbidden trust-promotion flags. Owner-only privileged MFA `GET /api/commercial-integrity/quotes/:id` now includes this read-only inspection and fails its combined `localScopeConsistent` on a locally inconsistent checkpoint, while returning no trusted external release assertions. If a quote has no candidate stream, it reports absent, not externally authenticated.
- CI `.github/workflows/ci.yml` runs new checksum-locked migration twice and `tests/bm-quote-checkpoint-mysql.integration.ts` against isolated real MySQL before established CRM/inventory/provider and Chromium MFA tests. The test suite checks concurrent competing Ed25519 candidate genesis/extension, fork/rollback, claimed publication conflict, local revocation claim, tampered previously committed HSN source, permanent quarantine after restoring source, forged persisted head and invalid/unpinned/forged signatures. `package.json` and `scripts/lib/stagingPreflight.ts` updated.
- The actual writer is **internal, opt-in and environment-guarded**. No new HTTP mutation endpoint, deploy permission, environment secret, private signer credential, outbound messages, trusted external key enrollment, invoice, PO, GRN, stock or accounting posting.

## Still required for real acceptance

A genuine *independently* pinned signing key cannot be established from an applicant-supplied PEM; key ownership, approved rotation and role-of-authority need authenticated external enrollment. Actual CRL/OCSP responses and issuer lineage require verified CCA/eMudhra scope, signing-policy assurance, CA certificate chain and independently refreshed authenticated revocation feeds. A claimed publication SHA, even one matching a locally verified candidate signature, is **not** evidence of remote publication. A real external, signed and independently retained **latest-head receipt**, provider-enforced Object Lock overwrite/delete denial, separately witnessed encrypted DR restored baseline, documented RTO/RPO and multi-authority Legal/OWNER/SECURITY/OPERATIONS review remain open.

**Anti-rollback limitation:** An administrator controlling both local MySQL history and candidate checkpoint ledger can rewrite an internally consistent tail and local head together. This local checkpoint ledger detects an *inconsistent* tamper but cannot guarantee that all past heads existed or remain complete. True independent rollback protection requires independently maintained, externally authenticated monotonic head custody *outside this system*, checked against a trusted legal/provider authorization chain. Do not consider test-signature pass as production authority.
