## Source-of-truth/security boundary

Phase 1BO records a **local, internally consistent applicant-provided** external-authority *dossier*. Neither a provider name, agreement digest, self-declared issuer, nor an Ed25519 signature by itself proves that a legally independent publisher has retained a monotonic checkpoint. Phase 1BP creates a controlled, offline **candidate evidence intake** interface for later independent provider onboarding, with a **server-issued short-lived one-use challenge** and four separate detached candidate signer roles: PUBLISHER, ISSUER, WORM and RECOVERY. This hardening is testable; it is **not** an actual external integration, real eMudhra/CCA authentication, external WORM, licensed CA, legal authorization or accepted DR. All claimed external evidence stays `CANDIDATE_UNVERIFIED`.

## Engineering changes

- `server/commercialIntegrity/quoteEvidenceIntake.ts`: exact-field, size-bounded, domain-separated canonical Ed25519 claim verification over challenge, quote ID, BO dossier SHA, BN candidate packet, BM candidate receipt, publication head, issuer chain/CRL/OCSP digests and revocation epoch/windows, Object Lock overwrite/delete-denial *claims*, purported retention horizon, restored source/receipt/sequence and RTO/RPO *claims*. Every one of four roles must be separately signed by a distinct candidate key with a distinct role/source identity. Cross-source disagreements, source rollback, stale/future time, CRL epoch regression, changed purported WORM denial and missing/forged signatures fail closed.
- **No public-key-in-packet trust:** signer public keys are supplied to the internal function in a separate `pinnedKeys` argument and strictly compared with an independently configured, exact SHA-256 pinset fingerprint, `BP_INTAKE_PINSET_SHA256`, on actual writes. A packet containing a public key or extra authority fields is structurally invalid. The current runtime **cannot attest that this configuration was enrolled by a legitimate external provider**; its CI keys are synthetic and cannot make a production signer trusted.
- `database/migrations/0039_bp_candidate_evidence_intake.sql`: FK-bound candidate intake stream, bounded append/incident attempt ledger, and server challenge table. DB columns for externally trusted enrollment, independent head retrieval, signed CRL/OCSP issuer verification, actual WORM denied-delete and witnessed DR are physically constrained to `NO`; production release stays `HOLD`. This local MySQL audit trail is not externally immutable.
- `server/commercialIntegrity/quoteEvidenceCustody.ts`: internal **no-HTTP** `issueCandidateIntakeChallenge` generates a random SHA-256 challenge under quote parent/source/BM/BN/BO transaction lock, persists a five-minute expiry and one-use issuance state, refuses issuance on prior quarantine or upstream corrupt state. `recordCandidateEvidenceIntake` re-reads actual quote/BO/BM/BN under the same parent lock, verifies all four candidate signatures and externally *configured* candidate pin SHA, validates the server challenge, records accepted internal candidate receipts or sticky fork/rollback/conflicting evidence/epoch regression/expired or replayed challenge quarantine. Exact latest replay is idempotent; changed signed payload using a consumed challenge is never a valid replay. Candidate head and accepted-attempt digest lineage, consumed challenge and all physically constrained external trust flags are verified on inspection.
- `scripts/migrate-bp-evidence-intake.ts` uses the exclusive migration advisory lock, checksums all 38 preceding migrations, checks schema drift and runs idempotently. Writes and migration only allowed on disposable CI database (`NODE_ENV=test`, `CRM_TEST_DB=1`, `DB_NAME=aaditech_ci`) or approved isolated TLS staging (`STAGING_DISPOSABLE_CONFIRMED=YES`, database `aaditech_staging_*`, `DB_SSL=true`, all prior BM/BN/BO explicit opt-ins **and** new `BP_INTAKE_WRITE_APPROVED=YES`). A distinct `BP_INTAKE_PINSET_SHA256` configured by a trusted operator is required for **candidate recording**; never store real provider keys or private secrets in chat/repo. Production writes and remote provider calls are denied.

## Genuine independence remains missing

To make these contracts meaningful outside synthetic fixture testing, obtain a **legally authorized and authenticated** named provider agreement and approved sandbox/production scope; independent provider/root certificate path validation; approved out-of-band and change-controlled signing-key pin enrollment; genuine provider endpoints with authenticated TLS, client identity and network isolation; independently retrieved signed monotonic checkpoint head retained by an **independent publisher** with a verifiable no-rollback baseline; real issuer-signed RCAI/CCA/eMudhra CRL/OCSP including signature, nonces, certificate policy, freshness, issuer authority and revocation distribution verification; verified cloud WORM retention/overwrite/delete denial tests from an independent account; real encrypted DR restoration independently witnessed against the remote head; verified company/MCA/GST/legal signatories and distinct authenticated OWNER/SECURITY/LEGAL/OPERATIONS release approvals.

The BP verifier sees **caller-supplied** alleged external bytes and a separately configured *candidate* Ed25519 pinset. It **does not actually fetch** third-party receipts, establish independent identity of those signers, perform X.509 CRL/OCSP authentication, prove provider WORM semantics or inspect a real disaster recovery restore. Even passing four candidate signatures cannot rule out one operator controlling all four test keys or jointly rewriting local MySQL history. The server-issued challenge protects **local replay**, not external anti-equivocation in isolation.
