## CI acceptance conditions

- `bun install --frozen-lockfile` must succeed on every test job.
- `tests/dependency-patches.test.mjs` verifies the exact expected versions, manifest overrides and Vite workspace consistency. `scripts/verify-patched-dependencies.mjs` re-checks the real lockfile and recomputed raw advisory triage; **any critical or high severity advisory** or retained targeted GHSA ID fails CI.
- Existing Phase 1U baseline gate also fails new/unreviewed advisories, severity increases, and mismatched audit reports.
- TypeScript, unit tests, production build, real disposable MySQL integrations, retention, HTTP auth and Chromium owner/reviewer MFA browser smoke must pass.
- `dependency-audit.json`, `dependency-triage.json`, and `dependency-baseline-status.json` remain available as CI artifacts.

## Caveats and release blockers

A clean `bun audit` for the current lockfile does **not** prove exploitability eliminated in every deployed build, nor prove there are no unknown vulnerabilities. There is no real deployed Hostinger staging scan, real TLS/physical-device MFA, actual encrypted restore rehearsal or independently measured RTO/RPO. No external customer sending was enabled. `productionReleaseAuthorized:false` remains mandatory even if current audit severity goes to zero.

**Changes require explicit security/owner acceptance before any merge or release.** Outbox stays HELD/DISABLED, real production MySQL unchanged, no host deployment or user provisioning.
