## Internal engineering

- `scripts/phase1bv-build-input-provenance.mjs` rejects changes to five known executable entrypoints (`dev`, `start`, `build`, `lint`, `test`) and any listed npm/Bun lifecycle installation/build hooks, unexpected workspace or locally patched dependencies, trusted-install scripts, or reverted frozen build tooling pin. It does not assume that a passed test makes all other custom scripts safe.
- The same checker examines the selected `vite.config.ts`: only declared React and Tailwind plugins, rejects dynamic glob source additions and `import.meta.glob`, runtime-supplied or variable glob patterns, unexpected matching libraries, optimizer/rollup dynamic entries; independently checks **both** dev and preview blocks for localhost-only, strict allowed hosts and port, disabled CORS; dev filesystem strict and HMR disabled. This is a **bounded source heuristic for an enumerated file, not full repository-wide taint analysis** or proof that Picomatch cannot be exploited internally by any dependency.
- Selected `server.ts` and `server/security/devToolExposure.ts` guards must retain the local Host gate, dynamic dev-only Vite import and hardened server options. The checker requires the documented local-only dev middleware boundary.
- CI source must retain only `push` and `pull_request` triggers (no `pull_request_target`/additional unreviewed entrypoint), global read-only `contents: read`, hosted `ubuntu-24.04` baseline/MySQL/production-scope runners, frozen normal and production-only Bun install, strict existing **zero Critical/High/unknown dependency advisory failure**, and the loopback Chromium MFA smoke with reliable server PID cleanup. Selected GitHub write-permission, unreviewed `environment:`/secrets entrypoint and remote-container execution indicators are rejected by the checker; this is not an exhaustive detection system for arbitrary commands in a changed workflow.
- On CI, the checker constrains the claimed source repository to **the correct AadiTech GitHub repo**, the ref to dev branch or a GitHub PR merge ref, and the claim to a 40-character SHA. These environment values and this workflow are not independently anchored by a separate authority; an attacker with sufficient repository/workflow write access can change code and controls.
- A bounded, exact-name **15-file SHA-256 inventory** hashes `.github/workflows/ci.yml`, `bun.lock`, `index.html`, `package.json`, `scripts/phase1bt-production-scope.mjs`, `scripts/phase1bv-build-input-provenance.mjs`, `scripts/phase1bz-actions-pin-preflight.mjs`, `scripts/verify-patched-dependencies.mjs`, `server.ts`, `server/security/deploymentGuards.ts`, `server/security/devToolExposure.ts`, `tsconfig.json`, `tests/phase1bv-build-input-provenance.test.mjs`, `tests/phase1bz-actions-pin.test.mjs`, `vite.config.ts`. A domain-separated digest binds file names, byte counts and SHA-256. The JSON artifact is written `phase1bv-held-build-input-report.json` with mode 0600 by the local script and uploaded by CI. **These 15 selected build-control inputs (including the verifier itself and its adversarial tests) are not the whole application source tree or a complete SBOM.** File path symlinks/nonregular files and oversize selected files fail closed.
- The new independent **`build-input-provenance`** hosted GitHub Actions job records that selected-file inventory and check. It remains separate from `baseline`, `production-runtime-scope`, and `mysql-integration`, so green scope/provenance cannot obscure an existing red zero-High global dependency audit. The artifact is labeled `UNSIGNED_LOCAL_CI_INPUT_INVENTORY`, not in-toto/SLSA, a hardware key signature, a separately witnessed CI audit, a genuine corporate receipt, or external WORM storage.
- `tests/phase1bv-build-input-provenance.test.mjs` adds nine adversarial tests: malicious shell/script substitution, prohibited lifecycle hooks, Bun lock/version/patch/installer modifications, Vite glob/plugin injection, direct dev CORS/HMR and separate preview drift, ungated Vite import, CI permission/trigger/runner/port-secret escalation, invalid repository/ref/commit, tampered/omitted/oversize hash inputs, and proof that **one known High vulnerability still fails the required release audit**.
