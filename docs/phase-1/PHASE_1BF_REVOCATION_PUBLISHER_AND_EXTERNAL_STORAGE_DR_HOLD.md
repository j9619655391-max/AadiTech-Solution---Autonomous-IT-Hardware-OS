## Threat boundary

Phase 1BE established an immutable-in-application **internal** candidate emergency freeze for a suspected witness signing key. Phase 1BF prevents an applicant-supplied "revoked" statement, applicant-controlled Ed25519 issuer SPKI or alleged CRL/OCSP hash from silently becoming a genuine independent revocation authority. A valid detached signature verifies only possession of a private key associated with a *self-supplied* public pin. It does **not** authenticate provider identity, CA certificate hierarchy, legal signatory, trusted publication channel, key custody or a real external operation.

Any candidate publication must bind to the **already recorded Phase 1BE frozen incident**, never clear or downgrade that incident, and remain audit-only.

## Implemented internal controls

- `scripts/lib/phase1BfRevocationPublication.mjs`: strict versioned, domain-separated `AADITECH_PHASE_1BF_REVOKED_WITNESS_PUBLICATION_HOLD_V1` payload with exact bounded fields. Binds candidate issuer SPKI, authority and claimed policy SHA-256; compromised witness SPKI and distinct surviving witness; Phase 1BE freeze incident, Phase 1AZ packet, Phase 1BD review SHA-256s; provider-reported revocation notice and prior snapshot; exact checkpoint/archive/object-version, claimed negative-delete Object Lock receipt and claimed encrypted-DR telemetry. The payload explicitly insists `REVOKED_CLAIMED`, `quarantineRequired=true`, `outboundHeld=true` and `releaseDecision=HOLD`. A claimed revocation is **not** actual proof.
- An applicant-supplied `REVOCATION_PUBLISHER` Ed25519 signature, the previously nominated surviving `WITNESS` signature, and existing `SECURITY` reviewer signature must verify the *same canonical bytes*. Publisher administrator and key must be disjoint from witness, provider/storage and governance reviewer identities; witness and security signers must match exact Phase 1BD candidate pins. The entire original Phase 1BE freeze signing set is reverified, not merely a previously reported boolean.
- Bounded UTC issued/observed/expiry timestamps, publication sequence and predecessor hash. Sequence 1 has a null predecessor; subsequent versions require nonzero SHA-256 previous publication. Refuse malformed/future/stale claims, unauthorized signing keys, extra fields, payload substitution, illegal GO and signs of suspect-key reuse.

A differing issuer, policy, claimed storage/DR audit or publication version produces a different hash.
