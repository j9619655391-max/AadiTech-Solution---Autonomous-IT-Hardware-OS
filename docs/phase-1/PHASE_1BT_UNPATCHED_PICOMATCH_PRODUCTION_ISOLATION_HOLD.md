## Actual vendor patch status

**CVE-2026-112366 / GHSA-fc5q-39xc-vjpf** is a HIGH-severity Regular Expression Denial of Service affecting Picomatch through `4.0.7` via repeated single-branch extglob input. On **17 November 2026**, the [reviewed GitHub Security Advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) says `Patched versions: None`, and the [npm published versions](https://www.npmjs.com/package/picomatch?activeTab=versions) still show `4.0.7` as latest. The upstream [PR #194](https://github.com/micromatch/picomatch/pull/194) was verified to be **open and is NOT a general patch** for this ReDoS; its own description says `+(*a)` remains vulnerable. No independently verified vendor fix or acceptable patched lockfile exists. **Do not invent a 4.0.8 release, cherry-pick an unrelated PR, suppress the advisory, or assert independent Security approval.**

The project's `bun.lock` includes `picomatch@4.0.7` through Vite `6.4.5` (`picomatch`) and tinyglobby (`picomatch`), originally declared along with React/Tailwind Vite plugins as production dependencies. This was a real production packaging exposure independent of whether untrusted patterns had been shown reachable. It is now **contained at the dependency-install boundary**, NOT patched inside Picomatch.

## Engineering controls implemented

1. `server.ts` no longer imports Vite at top level. `await import('vite')` is inside the existing `NODE_ENV !== 'production'` development-only middleware path. The production static asset path does not load Vite/picomatch. This is not proof of correct deployment configuration by itself; production is still blocked.
2. `package.json` and the exact frozen `bun.lock` workspace both move `vite`, `@vitejs/plugin-react` and `@tailwindcss/vite` **from `dependencies` to `devDependencies`**. Vite version remains precisely `6.4.5`, plugin ranges unchanged; no vendor version, SHA-512 package integrity, or advisory baseline has been misrepresented. Production dependency closure (dependency plus optional-dependency paths) reduces from **190 to 122 packages** in the known lock and no longer reaches `picomatch`/Vite/these plugins. Development CI still installs them, so the global advisory continues to report the High risk.
3. `scripts/phase1bt-production-scope.mjs` parses the checked-in Bun v2 lock without evaluating code; strictly compares the actual `package.json` dependency/dev-dependency constraints to Bun's workspace, requires all Vite plugins to be dev-only at pinned versions, rejects top-level Vite imports, validates the gated dynamic import, enumerates all locked production transitive dependencies and optional dependencies, rejects malformed/missing lock nodes or any production path to `picomatch`, Vite or the build plugins. It writes a local `phase1bt-production-closure-report.json` whose truthful flags continue to say `upstreamVendorFixVerified=false`, `independentSecurityApprovalVerified=false`, `productionReleaseAuthorized=false` and `HOLD`. This is not a vulnerability scanner or independent authority.
4. `tests/phase1bt-production-scope.test.mjs` exercises the real lock, injected direct/transitive Vite and Picomatch, lockfile tampering, missing reviewed plugins/keys, unguarded Vite import and the **separate** strict High dependency audit remaining red even when runtime closure is isolated. The existing `scripts/verify-patched-dependencies.mjs` has been made stricter: Vite must be pinned in **devDependencies only** and all related plugins isolated in both package and Bun lock; the function `checkCurrentAudit` still fails any Critical, High, or unknown vulnerability.

The containment evidence is archived separately and is explicitly *not* production approval. Existing baseline TypeScript/JS/build, real MySQL/Chromium and strict `bun audit` unchanged and remain mandatory.
