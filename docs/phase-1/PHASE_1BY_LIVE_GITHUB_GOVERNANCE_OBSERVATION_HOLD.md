## What was actually added

The new `scripts/phase1by-github-governance-observer.mjs` performs constrained **read-only GitHub REST requests from a separate Actions job**, using the native per-job GitHub token with **`contents: read` and `pull-requests: read`**. It requests only four static official GitHub API paths, with a fixed `https://api.github.com` origin, GET only, no redirects, bounded body length and timeout, no arbitrary requester-provided URLs, no raw secret output and bounded review pagination:

- `GET /repos/j9619655391-max/AadiTech-Solution---Autonomous-IT-Hardware-OS/pulls/1` — PR author, draft, open, unmerged, exact head/base SHA and API-provided test-merge SHA.
- `GET /repos/j9619655391-max/AadiTech-Solution---Autonomous-IT-Hardware-OS/pulls/1/reviews?per_page=100` — submitted GitHub review states, distinct non-author login and **most recent** valid review, bound to exact PR head commit. A stale/dismissed/CHANGES_REQUESTED/latest non-approval does not count.
- `GET /repos/j9619655391-max/AadiTech-Solution---Autonomous-IT-Hardware-OS/rules/branches/main` — observable **effective rules list**. Checks for PR requirement, at least two approvals, codeowner review, latest-push review, no force-push/deletion, and seven expected CI status contexts. **Reading an empty list is not proof that legacy branch protection is absent**, nor does the list independently prove all bypass actors are blocked.
- `GET /repos/j9619655391-max/AadiTech-Solution---Autonomous-IT-Hardware-OS/branches/main/protection` — additional legacy branch protection read, which can legitimately be denied by GitHub token permissions; a 403 is recorded **ACCESS_DENIED** and never assumed to mean enabled or disabled.

The job also compares live PR `head.sha` and `base.sha` with **GitHub event-provided** `github.event.pull_request.head.sha` and `github.event.pull_request.base.sha`, and compares live PR `merge_commit_sha` with the currently checked-out `GITHUB_SHA` test-merge. An updated PR head, forked repository, changed author, wrong PR ref, wrong base, merged/non-draft PR, mismatching or absent source SHA, or incomplete reviews is an explicit anomaly. A Github Push event does not qualify as PR approval evidence. Source metadata cannot establish a Security or business owner role without independently authenticated reviewer enrollment.
